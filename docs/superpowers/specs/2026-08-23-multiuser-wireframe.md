# 多用户 —— 前端改动线框图 / UI 规范

> 配套实施计划：`docs/superpowers/plans/2026-08-23-multiuser.md`（其 Task 6 以此为布局依据）。
> 本文件只描述**界面结构与交互**，不含数据层；数据行为见实施计划。

## 1. 登录页 `/login`

目标：未登录用户唯一入口，登录成功后跳转到 `/`。

```
┌──────────────────────────────────────────────┐
│                                              │
│              班主任智慧工作台                 │
│                   请登录                     │
│                                              │
│   ┌──────────────────────────────────────┐   │
│   │ 用户名  [__________________________] │   │
│   │ 密码    [__________________________] │   │
│   │                                      │   │
│   │        [ 登 录 ]  (primary, 整宽)    │   │
│   └──────────────────────────────────────┘   │
│                                              │
│   (居中卡片，暂不用背景图)                     │
└──────────────────────────────────────────────┘
```

行为：
- 提交校验非空；失败 toast「用户名或密码错误」并清空密码框。
- 成功 → `router.replace('/')`。
- 已登录用户直接访问 `/login` → 中间件放行后由前端跳回 `/`（或不特殊处理，靠 `/api/me` 判断）。

顶栏要素（从左到右）：
1. 汉堡菜单按钮（mobile 时显示）
2. 班级名称 `Typography.Text strong` = `/api/me` 的 `class.name`（无班则「班级工作台」）
3. 弹性空白 + 时间
4. 当前用户名（`/api/me` 的 `user.name`）
5. `退出` 按钮（调用 `/api/logout` → `router.replace('/login')`）
6. `编辑`/`完成` 切换（原功能保留）

侧边栏菜单差异：
- `role === 'admin'` 额外追加 `用户管理`（`/users`）。

## 4. 用户管理页 `/users`（仅 admin）

```
┌──────────────────────────────────────────────┐
│ 用户管理                                       │
│ [ ＋新增老师账号 ]                              │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ 用户名   姓名    角色    班级ID   操作        │ │
│ │ admin   系统管理员 管理员  -        -        │ │
│ │ demo    王老师    班主任   1        重置密码   │ │
│ │ lisi    李老师    班主任   2   重置密码 [删除] │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

「新增老师账号」弹窗：

```
┌─ 新增老师账号 ────────────────────────────┐
│ 用户名  [____________________]            │
│ 姓名    [____________________]            │
│ 密码    [____________________]            │
│ 班级名称 [____________________]            │
│         (留空则不新建班级)               │
│                    [取消]  [确定]          │
└──────────────────────────────────────────┘
```

行为：
- 只能创建 `role='teacher'` 账号；`班级名称` 非空则自动新建一个班级并绑定；否则绑定到已有 `classId`（本款由 API 层处理）。
- 行内 `重置密码` 用 `window.prompt` 输入新密码。
- `删除` 仅对非 admin 显示，需 `Popconfirm` 二次确认。

## 5. 系统设置页 `/settings`（改动后）

```
┌──────────────────────────────────────────────────────────────┐
│ 系统设置                                                       │
│                                                              │
│ ┌──────────────────────────┐   ┌─────────────────────────────┐│
│ │ 班级基础信息               │   │ 数据维护                     ││

│ │ 班主任   [____________]   │   │                             ││
│ │ 年级班次 [____________]   │   │ [备份数据库(下载app.db)]     ││
│ │         [ 保存 ]          │   │        ← 仅 admin            ││

│ └──────────────────────────┘   └─────────────────────────────┘│

```

行为：
- 班级基础信息由 `/api/me` 的 `class` 填充；保存走 `PUT /api/classes/:id`。
- `重置本班种子数据`：有 `class_id` 的账号可见，`POST /api/reset`（仅重置当前班）。
- `备份数据库`：仅 `role === 'admin'` 可见，`window.open('/api/backup')`。

## 6. 鉴权路由守卫

- 未登录访问任意页面 → 中间件重定向 `/login`。
- 未登录调 `/api/*` → 401，前端 `lib/api-client.ts` 跳转 `/login`。
- 已登录但无班级（admin）访问业务数据（如 `/students`）→ 数据为空列表，不报错。

```
访问 /students (未登录)
  中间件: 无 cookie → redirect /login
访问 /api/students (未登录)
  中间件: 无 cookie → 401 { error: '未登录' }
  api-client: 401 → location.href='/login'
```
